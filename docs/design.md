# 🏗️ Harness SkillOS 设计 · 三模式路由（v0.1 草案）

> 来源：和用户的设计讨论（2026-08-14）。这是 SkillOS 的核心机制：一个任务进来，怎么决定用哪些技能、要不要问人。

---

## 0. 一句话

任务进来 → harness 先看一张**路由表**（意图 → 技能）→ 根据命中情况选三种模式之一：**自动 / 确认 / 选择** → 加载技能干活。

## 1. 三种模式

| 模式 | 名字 | 什么时候用 | 怎么干活 |
|------|------|-----------|----------|
| ① | 自动模式（直接上） | 意图清晰 + 只命中 1 个（或 1 个配方） | 直接加载技能（**一个或多个**），干完收工，产出后过校验门 |
| ② | 确认模式（报菜名） | 命中 1 个但**高风险/不可逆/重要** | 先报菜名：「我要调用【X】，它是干【Y】的，对吗？」用户点头才加载 |
| ③ | 选择模式（端菜盘） | 命中 **2+ 个**，或意图模糊 | 端出候选菜单（每个一句话），用户选一个或几个（含组合配方），选完加载 |

> 模式③的隐藏价值：用户肉眼看到候选清单 = 发现「原来我还有这个技能」，顺带解决「不知道装了什么」的问题。

## 2. 模式决策规则（怎么选模式）

输入三样东西：**命中数量 + 意图清晰度 + 风险等级**

| 情况 | 模式 |
|------|------|
| 命中 0 个 | 先用通用能力干；干完问用户「要不要把这次沉淀成新技能」 |
| 命中 1 个，低风险，意图明确 | ① 自动 |
| 命中 1 个，高风险 / 不可逆 / 用户特意点名但描述存疑 | ② 确认 |
| 命中 2+ 个 | ③ 选择（按匹配度排序，给默认推荐） |

**风险分级（示例）**：只读 / 生成草稿 / 本地临时文件 = 低风险；删除 / 覆盖 / 花钱 / 发到外部 / 影响生产 = 高风险。

## 3. 和记忆管家联动（复利闭环）

- 每次用户**选择 / 拒绝 / 纠正** → 记录 → 更新路由表权重
- 技能用得越多 → **信任度升** → 自动模式更多（少打扰）
- 用户连续纠正 → **信任度降** → 下次转确认模式
- 长时间不用 → 休眠 → 归档（记录名字/能干什么/为什么卸载）→ 相似任务出现 → 主动问「要不要召回或找新的」

## 4. 问法模板（必须给用户清晰的回答）

- 确认模式：「我准备调用【X】——它是干【Y】的，对吗？确认后我就开工。」
- 选择模式：「这个任务有几个技能都沾边：A【…】、B【…】、C【…】。我推荐 A，你也可以选多个组合。」

## 5. 待定问题

- 默认模式倾向：用户希望「用到就问」当安全默认，但每次都问会烦 → 用信任度做自动放行
- 配方（组合）要不要也进选择菜单：建议进，和单个技能平级
- 路由表要不要记「负触发词」（什么时候别用）：建议记，专治相似技能跑偏


## 6. 多维度分类（技能档案）——用户已确认

**决定**：SkillOS 的分类不选一个固定体系，而是**四种视角全都要，每个技能打多个标签**。

### 每个技能配一张「技能档案」（skill profile）
| 字段 | 说明 |
|------|------|
| name | 技能名 |
| description | 做什么 + 何时用（触发全靠它） |
| 能力标签 | skills-tree 17 类（感知/推理/记忆/代码/数据/创意/安全…），可多个 |
| 用途标签 | Anthropic 9 类（库参考/验证/数据获取/业务流程/脚手架/质量/CI-CD/事故手册/运维），可多个 |
| 领域标签 | 市场 12 大领域 + 50 子类，可多个 |
| 动作角色 | 采集/处理/分析/生成/执行/校验/记忆，可多个 |
| 职业标签 | 可选（SOC 职业分类，按用户画像） |
| 负触发词 | 什么时候**别**用（专治相似技能跑偏） |
| 信任度/次数/上次使用 | 记忆管家维护 |
| 来源 + 版本 | GitHub/市场/自建 |

### 示例档案：一个「数据分析+图表生成」技能
- 能力标签：数据、推理
- 用途标签：产品验证、业务流程
- 领域标签：Data & AI
- 动作角色：分析 + 生成
- 负触发词：用户只要"格式转换"时别用（那是处理类）

### 多标签怎么被用到
- **快路径**：任务进来 → 意图 × description 匹配（还是最快）
- **模式③端菜盘**：候选可按任意维度过滤/分组展示（"分析类有这几个"）
- **浏览**："给我看看我有什么技能" → 按维度查（"写作类的"）
- **记忆管家**：按维度统计（"你三个月没用内容创作类技能了"）
- **召回**：相似任务来 → 用标签相似度找回归档技能

> 依据：SkillsMP 市场就是"一个技能可属多个分类"；skills-tree 还带版本（v1→v3）和基准测试，可借鉴到信任度机制。


## 7. 研究证据支撑（决策规则不是拍脑袋）——用户要求核查

**结论**：「命中数 + 意图清晰度 + 风险等级」这套判断，每一路都有学术界或业界主流依据。

| 决策输入 | 证据 | 来源 |
|---------|------|------|
| **命中几个 → 端菜盘（top-k）** | Microsoft 365 Copilot Orchestrator：从全部技能里取**最多 5 个**最匹配的候选；匹配顺序 = 词面→语义→动作名。业界主流就是"给候选清单" | learn.microsoft.com Orchestrator 文档 |
| **命中几个 → 重排** | SkillRouter：检索 + 重排技能选择，专门处理"近似重复技能"和"候选竞争" | arXiv 2603.22455 |
| **意图清晰度 → 是否先问** | EMNLP 2025《Learning to Ask》：指令不清楚就主动问；NAACL 2025《Clarify When Necessary》：高利害场景更要先澄清；ACL 2026《Value of Information》：低于置信阈值就触发提问 | aclanthology.org |
| **风险等级 → 确认门** | 伯克利 Agentic AI Profile：**超过风险阈值的动作必须人工授权**；社区 HITL 框架："安全操作保持自治，高风险功能插批准门" | law.stanford.edu；awesome-agentic-patterns |
| **信任度 → 自动放行** | 自适应自治（HATS）：按系统置信度/环境不确定性动态调节自治级别；"Statistical Priors"：个人 agent 用偏好统计选技能 | arXiv 2606.05828 等 |
| **确认门放哪（别乱问也别不问）** | CHI 2026《When Should Users Check?》：81% 用户偏好"中间确认"而非"最后才确认"，任务耗时降 13.54% | CHI 2026, doi:10.1145/3772318.3790655 |

### 一个必须记住的警告
Scale 的 HiL-Bench 实测：**AI agent 主动"求助/提问"的能力很差**——带 ask_human 工具的 agent 成功率上限只有约 30%。意思是：**确认门要"该问才问"，乱问反而拖垮表现** → 信任度机制（用得熟少打扰）不是加分项，是刚需。

### 一个工程细节
微软文档提示：单轮里触发 3 个以上动作可能失败 → "一个或多个技能"不是越多越好，要设上限（推荐 1-3 个）。


## 8. 户口模型：技能分几级（用户点名需求 + 直觉补充）

**决定**：不只"全局/项目"两级——用户直觉补充，业界也有依据。核心五级：

| 级别 | 作用范围 | 例子 | 生命周期 |
|------|----------|------|----------|
| **全局**（用户级） | 所有项目 | 常备工具箱 ~/.agents/skills/ | 永久 |
| **项目级** | 本项目 | <项目>/.agents/skills/ | 项目存续期 |
| **会话级** | 本次会话 | /careful 小心模式（Anthropic 内部实践） | 本次会话，用完即走 |
| **任务级** | 单次对话 | "这次别用 --force" | 当场有效 |
| **团队/组织级**（未来） | 多人共享 | 团队技能库 | 跟随组织 |

**覆盖顺序（越具体越优先）**：任务 > 会话 > 项目 > 全局。

**依据**：Anthropic 内部三层约束架构——永久规则进常驻配置、会话约束做成按需技能（/careful：今天想谨慎就开，会话结束自动消失）、任务约束写进对话内提示。

### 对 SkillOS 的影响
- 技能档案 scope 字段：global / project / session / task / team
- 路由表按「当前户口」过滤：只看到 全局 + 本项目 + 本次会话 的技能
- 会话级技能：临时加载、**自动过期**（会话结束即消失，不进入长期信任度记账）
- 记忆/信任度：全局和项目记账；会话/任务级即用即走，不记账
- 团队级：以后做"分享"功能时启用（把技能打成包发给团队/组织）

### 同名的覆盖规则
项目级覆盖全局级；会话级再覆盖项目级；任务级最高。


## 9. 自审：用调研知识重看设计（2026-08-14）

### 9.1 已经扎实的
- 三模式路由 + 决策规则：有研究证据（见第 7 节）
- 五级户口：Anthropic 三层约束架构支持
- 多维度技能档案：SkillsMP / skills-tree 支持
- 信任度机制：自适应自治研究支持

### 9.2 发现的洞 + 补丁
1. **路由表自己也会撑爆** → 路由表分层：**热区**（常驻 ≤20-30 个高信任技能的名片，只 name+description）+ **全库档案**（在硬盘上，浏览/搜索才读）。渐进式披露对自己也要用——否则技能一多，光路由表就把上下文烧了。
2. **技能档案缺 Gotchas** → 加"陷阱清单"字段（这个技能容易在哪翻车）。Anthropic 实测：带 Gotchas 的技能对准确率提升最明显，是最容易的加分项。
3. **技能要"养大"** → 生命周期路径：单文档 SKILL.md → 拆子文档 → 固化 scripts/；档案记版本；**改技能前问用户**（防记忆污染：技能文件被悄悄改写会塑造后续行为）。
4. **偏离必须报告** → 产出后校验门加铁律：没按技能步骤走就明说"我偏离了，因为…"，禁止闷声另搞一套（对应 Claude Code issue #58024：技能被静默替换）。
5. **问人也要省钱** → 批量确认、给默认推荐、"这次会话都自动"、"以后这类都自动"一键放行。理由：HiL-Bench 实测 AI 提问能力差，乱问伤表现。
6. **配方升级为一等公民** → 命名组合（如"资料文档链"）单独建档：有自己的户口/标签/信任度/版本，能存、能召回、能分享。
7. **反馈变测试用例** → 每次"你要的 ≠ 它给的"记成一条测试用例；攒到约 20 条跑一次回归，更新 description（agentskills 官方 eval 闭环：train/validation 6:4、触发阈值 0.5）。


## 10. 自审第二轮：再深一层（2026-08-14）

### 主题一：质量门（技能不是装上就完事）
1. **入库试用期**：新技能先进"试用区"，表现好才进热区；表现差（连续失败/被纠正）直接淘汰，不进路由表。依据：arXiv 生命周期有"验证/录取"阶段；研究结论"过时或不匹配的技能会增加成本、降低成功率"。
2. **退化检测**：模型升级或环境变化会让技能过时 → 连续失败 N 次 → 自动降级 + 问用户"更新还是卸载"。记忆管家加这条。
3. **粒度检查**：加技能时对照清单——太窄（一个任务要装好几个）或太宽（很难精确触发）都不好；目标是"一个可独立验收的任务单元"。

### 主题二：安全深度（来源和权限）
4. **来源信任等级**：档案加字段 官方 / 社区高赞 / 未知。未知来源安装前先人工审查（star 数≠安全）。
5. **权限需求**：档案记录"这个技能要碰什么"：文件 / 网络 / 密钥 / 外部账号。**碰的东西越多 → 越倾向确认模式**。脚本能访问文件和网络本身就是风险面。

### 主题三：好用度（让用户真用起来）
6. **内置技能模板（六大模式）**：SkillOS 自带的"新建技能"流程，直接生成带 陷阱清单 + 输出模板 + 检查清单 + 验证循环 + Plan-Validate-Execute + scripts/ 的模板——新手也能一键做出合格技能。
7. **定期能力盘点**：对抗"大部分团队只用 2-3 类技能"的问题——每月问一次"你还有 N 个没碰过的技能、M 个空类别，要不要看看"（接端菜盘）。
8. **显式点名快路径**：用户直接说"用 X" → 跳过路由匹配，直接走信任度 + 确认门（高风险仍先问，生疏也先问）。


## 11. 自审第三轮：验收与信任（2026-08-14）

### 视角一：怎么算成功
1. **验收标准**：每个技能档案必须写"**怎么算成功**"（验收标准）。产出后校验门从"AI 自检"升级为"**对照验收标准查**"。依据：研究结论"带明确验收标准的 Skill 更可靠"；Pydantic 说的 harness 本质是"把输出变成可验证、可持久的工作"。
2. **可验证产出优先**：技能模板原则——尽量产出"能检查的东西"（文件、diff、测试结果），而不是纯聊天文字。干完能验收，而不是"你信我"。

### 视角二：记忆的可信度
3. **记忆分信任层**：你**明说**的规则 = 高信任，直接用；我**猜测**的偏好 = 低信任，**先用再确认**。防止"猜错了还当真"，污染后面的路由。依据：Pydantic harness 的记忆三层（指令记忆/自动记忆/会话提取），信任度不同。
4. **版本快照 + 一键回滚**：每次改技能留快照，改坏了能退回上一版。这是"改技能前问用户"的安全兜底。依据：skills-tree 版本化演进 v1→v3。

### 视角三：运行环境的适配
5. **环境/兼容检查**：档案记"这技能要什么环境"（要联网？要特定系统/模型？）。**环境不满足时绝不自动调用，改问你**。依据：SKILL.md 的 compatibility 字段。
6. **技能依赖声明**：技能 A 可能需要技能 B 打底 → 档案记依赖，路由时自动带上。避免"调了 A 但缺 B"翻车。

### 视角四：懂用户
7. **画像驱动推荐**：结合用户目标（如远程求职、内容创作），主动推荐相关技能和配方——让 SkillOS 不只是"会用"，而是"懂你"。
